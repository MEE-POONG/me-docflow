# ME Docflow

ระบบจัดการเอกสารขององค์กรที่กำลังต่อยอดให้รองรับบัญชีคู่และเงินเดือน โดยข้อมูลทุกบริษัทแยกตาม tenant และตรวจสิทธิ์จากบัญชีที่เข้าสู่ระบบ

## สถานะการพัฒนา

อัปเดต ณ 30 ตุลาคม 2026

| สถานะ | ความหมาย |
|---|---|
| **เสร็จแล้ว** | โค้ดทำงานตามขอบเขตและผ่านการทดสอบเฉพาะทางในรอบนี้ |
| **ทำแล้ว** | มีความสามารถใน repository แล้ว แต่ยังต้องตรวจรับแบบครบเส้นทางหรือเชื่อมส่วนอื่น |
| **กำลังพัฒนา** | โค้ดเริ่มแล้ว แต่ยังมีงานเชื่อมต่อหรือทดสอบก่อนใช้งานจริง |
| **รอพัฒนา** | ยังไม่เริ่มทำ |

### ขอบเขตการใช้งานบัญชีและเงินเดือนในรุ่นนี้

- บัญชีคู่เก็บจำนวนเงินเป็นสตางค์ ตรวจยอดเดบิตและเครดิตให้เท่ากันก่อนบันทึก
- รายรับที่ยังไม่รับเงินตั้งลูกหนี้การค้า รายจ่ายที่ยังไม่จ่ายตั้งเจ้าหนี้การค้า การรับหรือจ่ายจริงสร้างรายการบัญชีอีกหนึ่งรายการเพื่อล้างยอดค้าง
- รอบเงินเดือนบันทึกค่าใช้จ่ายเงินเดือนและหนี้เงินเดือน/รายการหักค้างจ่าย เมื่อจ่ายจริงจึงลงบัญชีตัดเงินเดือนค้างจ่ายกับเงินสดหรือธนาคาร
- รายการเพิ่มและรายการหักเงินเดือนกรอกโดยผู้มีสิทธิ์ ระบบยังไม่คำนวณภาษี ประกันสังคม หรือรับรองการปฏิบัติตามกฎหมาย
- ผู้ดูแลเงินเดือนเห็นสลิปของพนักงานในบริษัท พนักงานทั่วไปได้เฉพาะสลิปที่อีเมลตรงกับบัญชีผู้ใช้ของตน

## ชุดจำลองเจ้าของ 2 บริษัท

**เสร็จแล้วสำหรับชุดจำลองนี้:** เพิ่มบริษัททดสอบแยก tenant ให้บัญชีเจ้าของเดิม โดยใช้ชื่อบริษัทลงท้าย `(ทดสอบ)` และใช้รหัสผ่านเดียวกับบัญชีต้นทาง ณ วันที่สร้างข้อมูล เมนูด้านบนแยกบริษัทที่เป็นเจ้าของออกจากบริษัทที่เป็นสมาชิก และโหลดสิทธิ์/หน้าจอใหม่หลังสลับบริษัท

บริษัททดสอบมี 2 แผนกและพนักงานตัวอย่าง 2 คน เงินเดือนตัวอย่าง 40,000 และ 25,000 บาทต่อเดือน ยังไม่สร้างรอบจ่ายหรือรายการบัญชีจากเงินเดือนเหล่านี้

สคริปต์สำหรับสร้างชุดเดียวกันในสภาพแวดล้อมที่ได้รับอนุญาต:

```bash
node --env-file=.env scripts/seed-two-company-demo.cjs --source-company-id "SOURCE_COMPANY_OBJECT_ID" --name "บริษัทที่ 2 (ทดสอบ)"
```

แทน `SOURCE_COMPANY_OBJECT_ID` ด้วย ID บริษัทต้นทางที่มีเจ้าของเปิดใช้งานเพียงคนเดียว สคริปต์เพิ่มบริษัท แผนก บัญชีเจ้าของ และข้อมูลพนักงานภายใน transaction เดียว การรันซ้ำกับบริษัทต้นทางเดิมจะคืนบริษัททดสอบเดิม จึงไม่สร้างข้อมูลซ้ำหรือคัดลอกเอกสาร/รายการเงินของบริษัทต้นทาง

เปิดหน้าระบบใหม่ → กดชื่อบริษัทมุมบน → เลือกบริษัททดสอบ → ยืนยันรหัสผ่าน → ตรวจรายชื่อพนักงานและหน้าเงินเดือนของบริษัทที่เลือก

ตรวจแล้ว: เมนูเจ้าของ 2 บริษัทบน desktop/mobile, รายการบริษัทยังคงอยู่หลัง reload, ข้อมูลพนักงานแยกตาม session บริษัท, ยอดเงินเดือนตัวอย่างรวม 65,000 บาท และรหัสผ่านผิดไม่เปลี่ยนบริษัท ชุดทดสอบสิทธิ์สลับบริษัท 3 กรณีและ TypeScript ผ่าน การยืนยันรหัสผ่านจริงในหน้าจอให้เจ้าของใช้รหัสผ่านเดิมของตน

## เทคโนโลยี

- Next.js 16 App Router และ React 19
- TypeScript
- Prisma 6 กับ MongoDB
- Tailwind CSS 4

## เริ่มต้นสำหรับนักพัฒนา

1. ติดตั้ง Node.js รุ่นที่รองรับและ dependencies:

   ```bash
   npm install
   ```

2. เตรียม `.env` โดยกำหนด `DATABASE_URL` สำหรับ MongoDB และ `SESSION_SECRET` ที่ยาวอย่างน้อย 32 ตัวอักษร อย่า commit `.env` หรือเปิดเผย connection string

3. ตรวจ schema และสร้าง Prisma Client:

   ```bash
   npx prisma validate
   npx prisma generate
   ```

4. ถ้ากำลังตั้งฐานข้อมูล **development/test ที่แยกจากข้อมูลจริง** ให้ซิงก์ schema:

   ```bash
   npx prisma db push
   ```

   แอปใช้ MongoDB transaction ในขั้นตอนสร้างรอบเงินเดือนและบันทึกการชำระ ฐานข้อมูลที่ใช้ต้องรองรับ replica set ก่อนนำ workflow เหล่านี้ไปใช้

5. เริ่มแอป:

   ```bash
   npm run dev
   ```

   เปิด `http://localhost:3000`

## ตรวจสอบการเปลี่ยนแปลง

```bash
npm run test:finance
npx tsc --noEmit
npm run lint
npm run build
```

`npm run test:finance` ใช้ fixture ในหน่วยความจำ ส่วน `npm test` รันชุดทดสอบทั้งหมดของ repository ซึ่งมี legacy tests ที่ยังต้องแยกตรวจสอบก่อนใช้งานกับฐานข้อมูล การตรวจแบบ end-to-end กับ MongoDB ต้องใช้ฐานทดสอบแยกและไม่ควรชี้ `DATABASE_URL` ไปข้อมูลบริษัทจริง

## บทบาทที่เกี่ยวข้อง

- **เจ้าของ / ผู้ดูแล / ฝ่ายบัญชี / ฝ่ายการเงิน**: จัดการผังบัญชี บิล และสมุดรายวัน
- **เจ้าของ / ผู้ดูแล / ฝ่ายบัญชี / ฝ่ายการเงิน / ฝ่ายบุคคล**: สร้างรอบเงินเดือน ดูและพิมพ์สลิปของพนักงาน และบันทึกการจ่าย
- **พนักงาน**: ดูและพิมพ์สลิปของตนเอง เมื่ออีเมลในข้อมูลพนักงานตรงกับอีเมลที่ใช้เข้าสู่ระบบ

ทุก Server Action ตรวจสิทธิ์ซ้ำจาก session และกำหนด `companyId` จากผู้ใช้ที่เข้าสู่ระบบ ไม่เชื่อ `companyId` ที่ส่งจาก browser
